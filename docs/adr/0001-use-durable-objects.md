# ADR 0001: 共有キャンバスに1つのDurable Objectを使用する

- ステータス: 採用
- 日付: 2026-08-11

## 背景

Goバックエンドでは、グリッドと接続中のWebSocketを1つのプロセスで保持しています。
Cloudflare Workerではリクエストが別々のisolateやロケーションで実行される可能性があるため、
同等の共有可変状態を安全に提供できません。

## 決定

初期版の共有キャンバスには、固定名の`CanvasDurableObject`を1つ使用します。Workerは
同一オリジンの`/ws` UpgradeをこのObjectへ転送します。Objectはセルの値をDurable
Objectストレージへ永続化し、Hibernation WebSocket APIですべての接続中ソケットを
調整します。

## 結果

- プロセスの再起動やObjectの退避後も状態が維持される。
- 共有キャンバスへのすべての描画が1つのObjectを通るため、一貫した更新順序を
  維持できる。
- このObjectがスケーラビリティの境界になる。1枚のキャンバスが過負荷になる場合は、
  プロトコルのバッチ化または複数ルームへの分割が必要になる。
- 将来ルームごとに異なるObject名を解決することでroom IDを追加できるが、これは今回の
  互換性移行の対象外とする。
